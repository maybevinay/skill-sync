# Database Design

## Platform

| Property | Value |
| --- | --- |
| Engine | PostgreSQL 16+ |
| Host | `localhost` |
| Port | `5432` |
| Username | from `POSTGRES_USER` (default `root`) |
| Password | from `POSTGRES_PASSWORD` (not committed in `.env`) |
| JDBC driver | `org.postgresql:postgresql` 42.7.4 |
| Migrations | Flyway + `flyway-database-postgresql` |
| ORM | Hibernate 6 / Spring Data JPA (`ddl-auto: validate`) |

Bootstrap SQL: `database/init/01-create-databases.sql`

## Database catalog

| Name | Service | Purpose |
| --- | --- | --- |
| `skillsync_auth` | auth-service | Identity, tokens, audit |
| `skillsync_matching` | matching-service | Skills, profiles, requests, reviews |
| `skillsync_ai` | ai-service | Chat memory, RAG, usage |

## Physical design notes

- Surrogate keys: `BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Booleans: PostgreSQL `BOOLEAN`.
- Timestamps: `TIMESTAMP` without time zone; Hibernate Instant mapped as `TIMESTAMP`.
- Cascades: refresh/reset/verify tokens and chat messages / rag chunks delete with parent.
- Logical `user_id` in matching/AI is **not** a FK to auth (separate databases).

## Table dictionary — auth

| Table | Description |
| --- | --- |
| `users` | Account; `role` VARCHAR; unique email |
| `refresh_tokens` | Hashed refresh JWT family; `revoked` |
| `password_reset_tokens` | One-time hash, expiry |
| `email_verification_tokens` | One-time hash, expiry |
| `audit_logs` | Action, details, optional actor and IP |

## Table dictionary — matching

| Table | Description |
| --- | --- |
| `skills` | Global catalog; unique name |
| `profiles` | One profile per `user_id` |
| `profile_skills` | Level + progress; unique pair |
| `mentor_profiles` | Headline, rating, review_count, accepting |
| `match_requests` | Learner → mentor, status |
| `reviews` | One review per request |

## Table dictionary — AI

| Table | Description |
| --- | --- |
| `chat_sessions` | Per-user conversation |
| `chat_messages` | `user` / `assistant` TEXT |
| `rag_documents` | Upload metadata |
| `rag_chunks` | Chunk text + embedding JSON |
| `ai_usage` | Approximate token counts by kind |

## Indexing (implicit)

Primary keys and UNIQUE constraints are the production indexes in V1. No pgvector IVFFlat/HNSW index: similarity is computed in Java.

## Connection configuration (services)

```yaml
spring:
  datasource:
    url: jdbc:postgresql://${POSTGRES_HOST:localhost}:${POSTGRES_PORT:5432}/skillsync_<context>
    username: ${POSTGRES_USER:root}
    password: "${POSTGRES_PASSWORD:...}"
  jpa:
    hibernate:
      ddl-auto: validate
  flyway:
    enabled: true
```

Tests use H2 in PostgreSQL compatibility mode (`MODE=PostgreSQL;DATABASE_TO_LOWER=TRUE`).

## Integrity rules

- Email uniqueness globally in auth.
- Cannot attach the same skill twice to a profile.
- One mentor profile per profile.
- One review per match request.
- Chat/RAG rows always include `user_id` for tenant isolation at query time.

## Future (not implemented)

- `CREATE EXTENSION vector` and native `vector(n)` columns.
- Cross-database referential integrity via saga or shared user service.
